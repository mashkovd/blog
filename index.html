04 · Boundary

Why hide the issue from the implementer?

Because “go read everything and infer intent” is exactly how agentic workflows become non-auditable.

Before approval

Proposer

Reads the issue, investigates context, writes a complete proposal.

Gate

Human approval

A person decides whether the contract is acceptable.

After approval

Implementer

Executes the contract, not hidden chat context.

06 · Control model

Humans decide whether. Claude decides how.

The loop separates judgement from execution. Human approval is durable; automated review is evidence-bound.

Human gate

Approve

Is this the right change? Is the proposal complete? Is the risk acceptable?

intent → durable approval signal

Automated gate

Review gate

Does the current PR head pass checks? Are blocking findings resolved? Is the evidence current?

head SHA + CI + reviews → gate result

08 · Review gate

The reviewer blocked real issues.

Claude did not just say “LGTM”. It found blocking P2s and named exact files and invariants.

P2

ADR headings

Bare English headings could pass the bilingual body check.

P2

Project pairs

English and Russian project files could drift or miss a pair.

P2

Tests not run

The new test script existed but was not executed by CI or image build.

The reviewer reads the current diff. The gate blocks unresolved evidence, not vibes.
09 · What broke

The useful part is what failed.

The loop got better because failures were turned into rules future agents must follow.

PR #17

Lockfile trap

npm install pruned native optional dependencies. Rule: regenerate lockfiles with --package-lock-only.

PR #19

try/catch was the wrong rule

Storage failure made toggles inert. Rule: losing localStorage must cost persistence, not function.

PR #29

Uncommittable criteria

The implementer cannot edit the PR body. Rule: acceptance criteria must be satisfiable by a commit.
